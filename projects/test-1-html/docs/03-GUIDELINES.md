# 📐 GUIDELINES — قوانین کدنویسی این پروژه
**نسخه:** 1.0.0 | **تاریخ ایجاد:** 2026-11-15 | **آخرین آپدیت:** 2026-11-15

> هر قانون اینجا با یک ✅ درست و یک ❌ غلط نوشته می‌شود.

---

## ۱. اصل ماژولاریتی — مهم‌ترین قانون

هر فایل دقیقاً **یک** مسئولیت دارد؛ اگر توضیح فایل به «و» نیاز داشت، دو فایل شود. سطح انتخابی این پروژه: **سبک** (متن‌ها یک‌جا، کانفیگ جدا، استایل جدا).

### ✅ درست:
```js
// config/app.js — فقط هویت برنامه
window.APP_CONFIG = { name: '…', creator: '…' };
```

### ❌ غلط:
```js
// یک فایل که هم هویت برنامه، هم متن دکمه‌ها، هم رفتار کلیک را نگه می‌دارد
```

---

## ۲. سقف حجم فایل

| زبان | سقف هر فایل | چرا |
|---|---|---|
| JavaScript | ~۱۵۰ خط | کد فشرده، import/export سبک |
| CSS صفحه | ~۱۵۰ خط | استایل کیت جدا و دست‌نخورده است |

---

## ۳. متن‌های قابل‌مشاهده به کاربر — یک‌جا، نه پخش

متن صفحه (تیتر، دکمه، پیام) فقط در `index.html` نوشته می‌شود؛ هویت برنامه فقط در `config/app.js`. JS هیچ رشته‌ی رو‌به‌کاربر ندارد.

### ✅ درست:
```js
message.textContent = button.dataset.message;
```

### ❌ غلط:
```js
message.textContent = 'رشته‌ی خام وسط منطق';
```

---

## ۴. پیکربندی — هرگز هاردکد نشود

اسم برنامه فقط در `config/app.js` تایپ می‌شود (`check_name.py` این را بررسی می‌کند).

### ✅ درست:
```js
document.title = APP_CONFIG.name;
```

### ❌ غلط:
```js
document.title = 'نام برنامه به‌صورت دستی';
```

---

## ۵. مدیریت خطا — یک الگوی ثابت

عنصری که ممکن است در صفحه نباشد، قبل از استفاده بررسی می‌شود و در نبودش تابع بی‌صدا برمی‌گردد.

```js
const el = document.querySelector('[data-x]');
if (!el) return;
```

---

## ۶. نام‌گذاری و صادرات

- نام فایل‌ها kebab-case.
- هیچ متغیر سراسری جز یک نام‌فضا (`APP_CONFIG`)؛ هر اسکریپت در یک تابع بسته (IIFE) می‌ماند.

---

## ۷. مستندسازی توابع

هر تابع یک توضیح یک‌خطی بالای خودش دارد: چه کاری می‌کند، نه چطور.

---

## ۸. طراحی (taste-skill)

ظاهر طبق `design-taste-frontend` ساخته و با gate آن بررسی می‌شود. فایل‌های کیت (`assets/`) دست‌نخورده می‌مانند و FAIL با تغییر کیت یا مخفی‌کردن از چک‌کننده رفع نمی‌شود؛ هر FAIL غلط با دلیل در `.taste-skill/waivers.json` معاف می‌شود.

---

## ۹. بعد از هر تغییر

بعد از هر تغییر کد، `docs-sync` همان لحظه سند را به‌روز می‌کند و `git-checkpoint` کد و سند را در یک commit می‌گذارد.
